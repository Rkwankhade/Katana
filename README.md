# AETHER

Frontend-only Next.js (static export), React, TypeScript, Tailwind, GSAP ScrollTrigger, Motion, Lucide. No backend.

## Run
    npm install
    npm run dev          # http://localhost:3000
    npm run build        # static site in ./out
    npx serve out        # preview the build (any static host works)

The host must support HTTP Range requests (all common static hosts do) so the video can be scrubbed.

## Notes
- Hero video: public/media/aether-hero.mp4 is the byte-identical original (sha256 d9cf2a8a...c4d8). Never re-encoded.
- Timeline source of truth: src/data/chapters.ts
- Illustrative SVG imagery is generated by scripts/gen-images.mjs (node scripts/gen-images.mjs).
- Samurai artwork (parallax layers, katana, crest, and the four "Samurai heritage" destination scenes) is generated by scripts/gen-samurai.mjs (node scripts/gen-samurai.mjs). Layers land in public/img/samurai/.
- Samurai UI lives in src/components/samurai/: Reveal (scroll reveals), ScrollProgress, Petals (sakura canvas), SamuraiDivider, PathOfSamurai (GSAP parallax scene), Bushido (pinned horizontal hanging scrolls).
- Hydration: src/app/layout.tsx sets suppressHydrationWarning on <html> and <body> only, because browser extensions inject attributes there before React hydrates. The inline boot script (below) also sets data-* attributes on <html> before paint, which falls under the same suppression.
- Reduced motion and Calm: parallax, pinned scrolls, petals, video scrubbing and reveals are all disabled; Bushido becomes a swipe row on every screen size. Both come through the single `useMotionOK()` hook.
- User data lives in LocalStorage under keys prefixed "aether:v1:".

## Phase 1 foundation (preferences, motion, tiers, director, settings)

Scripts: `npm run typecheck`, `npm run build`, `npm test` (Node tests, no extra dependencies; run `npm run build` first to include the check of the built boot script).

- **Preferences**: `src/lib/preferences-core.ts` (types, defaults, field-by-field validation), `preferences-store.ts` (localStorage under `aether:v1:prefs`, corrupt-value backup to `aether:v1:prefs:corrupt`, cross-tab sync), `preferences.tsx` (provider and hooks). The provider is mounted in `src/app/layout.tsx`, so every route has it. Server and first client render use defaults; saved values arrive after hydration via `useSyncExternalStore`, so there is no hydration mismatch.
- **No flash**: `src/lib/bootScript.ts` is inlined in `<head>` and sets `data-calm`, `data-tier` and `data-still` on `<html>` before paint. CSS (`globals.css`) uses them, and the cinematic's height comes from `--cinema-h`, so Calm and static layouts do not jump after hydration. It reuses `detectCapability` by serialising the function, and the production build is tested for this.
- **Motion**: `useMotionOK()` is true only when neither the OS reduced-motion setting nor the Calm setting asks for less. Reveal, Petals, PathOfSamurai, Bushido, Cinematic, ScrollProgress and smooth-scroll calls use it. `useTier()` is the effective capability tier.
- **Tiers** (`src/lib/capability.ts`): 0 static (poster and artwork, no particles, no scrubbing), 1 reduced (half the petals, no mist or blossom parallax), 2 full. Detection uses data-saver, `prefers-reduced-data`, 2G, device memory, core count and viewport as hints; one weak hint never lowers the tier. Visitors can override it under Settings > Performance.
- **Animation director**: `src/lib/director.ts` runs per-frame work (video seek easing, petals) on GSAP's ticker. `src/lib/scrollHub.ts` provides one shared, coalesced window scroll listener and one resize listener for plain UI (header, progress, petals, capability). It has no GSAP import, so the privacy and terms pages stay light. ScrollTrigger scenes (cinematic, parallax, Bushido) are unchanged and remain owned by their components.
- **Hero media**: `src/data/media.ts` is the integration point for footage. `master24` (the planned 24 second master) and `lightweight` are `null` because that footage does not exist here. A master needs its own chapter table in `src/data/chapters.ts` before it is enabled. The video element loads with `preload="metadata"` and is raised to `auto` only when scrubbing starts; on tier 0, Calm and reduced motion, only the poster is shown.
- **Settings**: `src/components/SettingsMenu.tsx`, opened from the header on every page. Browsing mode, season, Calm, ambient sound, sound effects and master volume are stored now. Season, Guided Story and sound have no visible or audible effect yet; they are persisted contracts for later phases. Nothing plays audio.

## Phase 2: living world and seasonal environments

- **Seasons** (`Auto`, `Spring`, `Summer`, `Autumn`, `Winter`, plus a Northern/Southern hemisphere choice that only matters for Auto). `src/lib/season-pick.ts` is the single selection rule; the inline boot script serialises it, so `html[data-season]` is correct before first paint and a refresh never flashes. `useSeason()` returns "spring" on the server and during hydration, then the real season in the same pass hydration finishes, so markup never depends on the build date.
- **Palette**: CSS custom properties in `globals.css` (`--s-sky-*`, `--s-glow-*`, `--s-veil-*`, `--s-prog-*`), defined once and used both by `html[data-season]` and by crossfaded `.sb` layers (`SeasonBackdrop`). Layers fade on opacity only; the outgoing layer is dropped after the incoming one is opaque. The hero video is never touched; the seasonal veil (`SeasonAtmosphere`) is off while the cinematic intro is on screen.
- **Seasonal artwork**: `scripts/gen-samurai.mjs` now also writes `branch-{summer,autumn,winter}[-left].svg`, reusing the sakura trunk. Existing assets are byte-identical after regeneration. `SeasonBranch` mounts only seasons that have been shown, so a visitor downloads one branch image per side, not four.
- **Particles**: `Petals.tsx` is still the only particle system. Kinds: petals (spring, unchanged look), fireflies (summer), maple and ginkgo leaves (autumn), snow (winter). Rules and maths live in `src/lib/particles.ts` (budgets, pointer force, scroll wind, fades) and are unit-tested. Changing season fades one set out and the next in; the loop is not rebuilt.
- **Pointer**: mouse and pen only (touch is never tracked). Particles within 120px are pushed with a smoothstep falloff, then damped back to their own drift. One passive `pointermove` listener exists only while particles are allowed; the canvas is `pointer-events: none`.
- **Scroll**: velocity comes from the existing shared scroll hub callback; it becomes a clamped wind (max 55 px/s): downward scrolling adds fall, upward scrolling a gentle lift.
- **Crests**: `Crest` (glow halo as a separate element, transform and opacity only). Header crest pulses and takes a quarter turn when the current section changes; divider crests pulse on reveal; the footer crest turns only while visible (`FooterCrest`); Bushido seals stamp once when 55% of a scroll is on screen. All use one shared observer (`src/lib/visibility.ts`) and are off when `html[data-still="true"]` (Calm, reduced motion, tier 0). `CrestBloom` is the integration point for the journey map; it is intentionally not mounted yet.

## Phase 3: interactive katana reveal

- **Where**: `SamuraiDivider variant="katana-reveal"` replaces the first plain katana divider (right after the cinematic). The second plain katana divider is unchanged. The plain dividers are about 35px tall, too small to be a 44px control or to show a dragon engraving, so they stay decorative; the pinned Bushido section is untouched because it is already close to one viewport tall.
- **`KatanaReveal`** (`src/components/samurai/KatanaReveal.tsx`): inline SVG with distinct layers: steel blade with a single bright edge bevel, wavy hamon, kurikara dragon engraving, tsuba, black ito-wrapped tsuka with menuki, gold habaki, fuchi and kashira, lacquered saya with gold koiguchi and kojiri, red sageo.
- **Geometry** (`src/lib/katana-geometry.ts`): the blade is a circular arc, and the draw is a rotation about the arc's centre, so the blade follows its own curve out of the curved saya (15% of its length). Unit tests check the plausibility invariants (tip stays inside the saya, tsuba meets the mouth at rest, pommel stays in the box).
- **Interaction** (`src/lib/katana-state.ts`, a pure state machine): mouse and pen hover or keyboard focus draw the blade; a click toggles drawn. Touch never hovers: first tap draws, second sheathes. A native `<button>` with `aria-pressed`, so Enter and Space work untouched.
- **Motion** is CSS transitions on `[data-open]` (transform and opacity only, no filters, no JS loop), so the Calm, reduced-motion and tier-0 rules apply for free. In those modes the sword is shown drawn with every marking visible and nothing moves (a click still toggles instantly). Tier 1 skips the glint.
- **Virtues**: `src/data/virtues.ts` is shared with the Bushido scrolls. The seven markings are gold outlined glyphs on the saya (`src/data/virtue-glyphs.ts`, generated by `scripts/gen-virtue-glyphs.py` from Noto Serif CJK JP Bold, SIL OFL 1.1), so no font is assumed. Their names and meanings are always visible as text under the sword.
- **Sound** (`src/lib/sfx.ts`): a synthesised Web Audio effect (breath of filtered noise, faint metallic ring). Off by default, played only from the click that draws the sword and only when Sound effects is on; hover, focus and sheathing are silent. One lazily created AudioContext, one sound at a time with a cooldown, every node disconnected when it ends. Without AudioContext nothing happens and the animation is unaffected.
